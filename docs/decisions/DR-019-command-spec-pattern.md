# DR-019: Command Spec Pattern

**Status:** Accepted (reconstructed)
**Reconstructed:** 2026-06-12 from spec references, code, and git history; the original record was never written.

## Decision

All per-command configuration is consolidated into a single `command_spec/1` function returning a spec map with keys `:command`, `:execution`, `:settle`, `:shrink`, `:when`, `:with`, `:weight`. The moduledoc states the model explicitly: "This follows the proven `child_spec/1` pattern from Elixir's standard library." Resolution uses three-tier priority: call-time overrides from the model's command list > module defaults from `use PropertyDamage.Command, ...` options > framework defaults. Legacy callbacks (`semantics/0`, `settle_config/0`, `read_only?/0`) keep working as fallbacks when `command_spec/1` is absent.

Introduced by commit `2e64ef6` ("feat: add command_spec/1 pattern for unified command configuration").

Evidence level: high; pattern, priority layering, and migration table are all documented in code and spec.

## Context

(Inferred plus documented analogy.) Before the spec pattern, command configuration was scattered across several optional callbacks (`semantics/0`, `settle_config/0`, `read_only?/0`) plus model-side options (`when:`, `with:`, `weight:`), with no single place to see or override a command's full behavior. Elixir already solved the same problem for supervised children with `child_spec/1`: a default generated by `use`, customizable via `use` options, overridable at the call site. Adopting the same shape gives commands sensible defaults with layered overrides, makes model command lists (`Module`, `{Module, opts}`, `%{command: Module, ...}`) uniform, and provides a stable map for tooling.

## Consequences

- `lib/property_damage/command.ex`: spec map structure, `use` macro generating the default `command_spec/1`, `framework_defaults/0`, legacy-callback fallback (`get_legacy_semantics/1` etc.), and the migration table mapping legacy callbacks to spec fields.
- `openspec/specs/command/spec.md` requirements "Command Spec Pattern" and "Spec Priority Layering" (e.g. module `execution: :probe` overridden by model `execution: :async`).
- `openspec/specs/model/spec.md` "Command Specification Formats": every accepted format normalizes to `{weight, module, spec}` via `command_spec/1`.
- Framework defaults pinned in the spec: `execution: :sync`, `shrink: :neutral`, `weight: 1`, `when` always-true, `with: %{}`, settle `timeout_ms: 2000, interval_ms: 300, backoff: :linear`.
