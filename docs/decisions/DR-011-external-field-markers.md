# DR-011: External Field Markers

**Status:** Accepted (reconstructed)
**Reconstructed:** 2026-06-12 from spec references, code, and git history; the original record was never written.

## Decision

Fields whose values are generated by the SUT are declared on **event structs** with an `external()` marker as the field default (e.g. `defstruct [id: external(), :amount]`). The framework detects external fields automatically, captures their concrete values from adapter-returned events during execution, and uses them to resolve downstream references. This replaces the command-level declaration of refs (`creates_ref/0` plus `Ref.symbolic/1` in generators), which is deprecated.

Additionally, domain libraries that must not depend on PropertyDamage can use their own marker atoms, registered via the `external_markers:` run option or app config.

Evidence level: high; introduced by commit `86f86e8` ("feat: add external() marker for server-generated values"), with the migration rationale written into `lib/property_damage/ref.ex`.

## Context

The deprecation note in `lib/property_damage/ref.ex` states the recorded rationale: the new approach offers "Multiple external fields per event", "Nested externals in maps and fixed-length lists", "Automatic detection without command-level configuration", and "Cleaner separation of concerns (externals declared on events, not commands)". (Inferred elaboration:) declaring server-generated values on commands was backwards: it is the *event* that carries the server-generated value, and one command could only declare a single ref. Marking events keeps commands pure (DR-006) and lets the framework track arbitrary external paths like `[:ids, :transaction]`.

## Consequences

- `PropertyDamage.external/0` is the marker (imported as `external()` in event struct definitions); see the migration example in `lib/property_damage/ref.ex`.
- `openspec/specs/execution-engine/spec.md` requirement "External Field Markers": single, multiple, and nested external fields with independent resolution.
- `lib/property_damage/options.ex` `external_markers:` option: "allows domain libraries to mark server-generated fields without depending on PropertyDamage" (e.g. `:__external__`), combined with `config :property_damage, external_markers: [...]`.
- `creates_ref/0` survives only as documented legacy metadata in `lib/property_damage/command.ex`; guides were updated to the new API (commit `721461d`).
