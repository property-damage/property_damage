# Scaffold Templates

How spec sections become files. You write these files directly (never via
`mix pd.gen.*` - their flags cannot carry the spec). Every generated file
opens with a header comment naming its regeneration class; keep the wording:

- regenerable: `# Generated by pd-model-interview from model_spec.md (class: regenerable).`
- adapter: `# Scaffolded by pd-model-interview (class: hand-owned). Yours after the first edit.`

Layout per model (from the spec's `dir:`): `model.ex`, `commands/` (one file
per command), `events/` (one per event), `projections/` (one per projection),
`adapter.ex`, next to `model_spec.md`.

The worked example below is a complete miniature model - a wallet service -
in exactly the shape the scaffold should produce. Its code blocks are
executed by the repository's doc-verification gate against the current
framework, so if these templates compile and run, your scaffold built from
them will too.

## The spec being scaffolded (excerpt)

```yaml
model: Wallets
namespace: MyStore.PD.Wallets
transport: in_process
reset: fresh instance per adapter setup
```

Commands: `OpenWallet` (sync, no fields, events: [WalletOpened]) and
`Deposit` (sync, fields: `wallet_id` (an existing wallet), `amount`
("positive cents"), when: "at least one wallet exists", weight: 3,
events: [Deposited]). Invariant `no_negative_balance` (trigger, every step).

## The system under test

The real SUT is the user's application. Here a tiny in-process stand-in keeps
the example self-contained:

<!-- pd-doc-verify: runnable -->
```elixir
defmodule MyStore.WalletService do
  # Stand-in SUT. In a real project this module already exists - it IS the
  # system; the adapter below is the only place that touches it.
  def start_link, do: Agent.start_link(fn -> %{} end)
  def stop(pid), do: Agent.stop(pid)

  def open_wallet(pid) do
    id = "w_#{System.unique_integer([:positive])}"
    Agent.update(pid, &Map.put(&1, id, 0))
    {:ok, id}
  end

  def deposit(pid, id, amount) when is_integer(amount) and amount > 0 do
    Agent.get_and_update(pid, fn wallets ->
      case wallets do
        %{^id => balance} ->
          {{:ok, balance + amount}, %{wallets | id => balance + amount}}

        _ ->
          {{:error, :unknown_wallet}, wallets}
      end
    end)
  end
end
```

## Commands

Generator notes from the spec become StreamData generators. A field that
references an existing entity (`wallet_id`) defaults to `nil` here; the
model's `with:` option supplies it from projection state.

<!-- pd-doc-verify: runnable -->
```elixir
# test/support/pd/wallets/commands/open_wallet.ex
# Generated by pd-model-interview from model_spec.md (class: regenerable).
defmodule MyStore.PD.Wallets.Commands.OpenWallet do
  use PropertyDamage.Command

  defstruct []

  @impl true
  def generator(_overrides \\ %{}), do: StreamData.constant(%{})
end

# test/support/pd/wallets/commands/deposit.ex
# Generated by pd-model-interview from model_spec.md (class: regenerable).
defmodule MyStore.PD.Wallets.Commands.Deposit do
  use PropertyDamage.Command

  import PropertyDamage.Generator, only: [merge_overrides: 2]

  defstruct [:wallet_id, :amount]

  @impl true
  def generator(overrides \\ %{}) do
    %{
      # spec: "an existing wallet" -> supplied by the model's with: option
      wallet_id: nil,
      # spec: "positive cents"
      amount: StreamData.positive_integer()
    }
    |> merge_overrides(overrides)
    |> StreamData.fixed_map()
  end
end
```

Spec `semantics:` maps to `use` options: `sync` is the default bare
`use PropertyDamage.Command`; `probe` and `async` become
`use PropertyDamage.Command, execution: :probe` (or `:async`). Read-only
commands also take `shrink: :prefer_remove`.

## Projections

State exists because a guard or an invariant needs it - nothing speculative.

<!-- pd-doc-verify: runnable -->
```elixir
# test/support/pd/wallets/projections/model_state.ex
# Generated by pd-model-interview from model_spec.md (class: regenerable).
defmodule MyStore.PD.Wallets.Projections.ModelState do
  use PropertyDamage.Model.Projection

  alias MyStore.PD.Wallets.Events.{Deposited, WalletOpened}

  @impl true
  def init, do: %{wallets: %{}}

  @impl true
  def apply(state, %WalletOpened{wallet_id: id}) do
    put_in(state, [:wallets, id], 0)
  end

  def apply(state, %Deposited{wallet_id: id, balance: balance}) do
    put_in(state, [:wallets, id], balance)
  end

  def apply(state, _), do: state
end

# test/support/pd/wallets/projections/balance_invariants.ex
# Generated by pd-model-interview from model_spec.md (class: regenerable).
defmodule MyStore.PD.Wallets.Projections.BalanceInvariants do
  use PropertyDamage.Model.Projection

  alias MyStore.PD.Wallets.Events.{Deposited, WalletOpened}

  @impl true
  def init, do: %{balances: %{}}

  @impl true
  def apply(state, %WalletOpened{wallet_id: id}) do
    put_in(state, [:balances, id], 0)
  end

  def apply(state, %Deposited{wallet_id: id, balance: balance}) do
    put_in(state, [:balances, id], balance)
  end

  def apply(state, _), do: state

  # spec invariant: no_negative_balance (trigger, every step).
  # Severity: money leaves the books - catastrophic.
  @trigger every: 1
  def assert_no_negative_balance(state, _cmd_or_event) do
    case Enum.find(state.balances, fn {_id, balance} -> balance < 0 end) do
      nil -> :ok
      {id, balance} -> PropertyDamage.fail!("negative balance", wallet: id, balance: balance)
    end
  end
end
```

A `poll_state` invariant (eventual consistency) has this shape instead - the
function returns a predicate polled until true or timeout:

    @poll_state after: PaymentInitiated, timeout: 5, interval: {100, :milliseconds}
    def payment_confirmed(_state, %PaymentInitiated{id: id}) do
      fn state -> state.payments[id] == :confirmed end
    end

## Model

Spec `when:` prose becomes the `when:` guard; entity-reference fields get
their `with:` override; spec weights carry over.

<!-- pd-doc-verify: runnable -->
```elixir
# test/support/pd/wallets/model.ex
# Generated by pd-model-interview from model_spec.md (class: regenerable).
defmodule MyStore.PD.Wallets.Model do
  @behaviour PropertyDamage.Model

  alias MyStore.PD.Wallets.Commands.{Deposit, OpenWallet}
  alias MyStore.PD.Wallets.Projections.{BalanceInvariants, ModelState}

  @impl true
  def commands do
    [
      {OpenWallet, weight: 1},
      {Deposit,
       weight: 3,
       # spec: "at least one wallet exists"
       when: fn state -> map_size(state.wallets) > 0 end,
       with: fn state ->
         %{wallet_id: StreamData.member_of(Map.keys(state.wallets))}
       end}
    ]
  end

  @impl true
  def command_sequence_projection, do: ModelState

  @impl true
  def assertion_projections, do: [BalanceInvariants]

  @impl true
  def injectable_events, do: []
end
```

## Adapter

Hand-owned after the first scaffold. Confirmed wiring gets real clauses;
everything unconfirmed is a TODO stub that raises loudly.

<!-- pd-doc-verify: runnable -->
```elixir
# test/support/pd/wallets/adapter.ex
# Scaffolded by pd-model-interview (class: hand-owned). Yours after the first edit.
defmodule MyStore.PD.Wallets.Adapter do
  use PropertyDamage.Adapter

  alias MyStore.PD.Wallets.Commands.{Deposit, OpenWallet}
  alias MyStore.PD.Wallets.Events.{Deposited, WalletOpened}

  @impl true
  def setup(_config) do
    # spec reset strategy: fresh instance per adapter setup
    {:ok, sut} = MyStore.WalletService.start_link()
    {:ok, %{sut: sut}}
  end

  @impl true
  def teardown(%{sut: sut}), do: MyStore.WalletService.stop(sut)

  @impl true
  def execute(%OpenWallet{}, %{sut: sut}, _runtime) do
    {:ok, wallet_id} = MyStore.WalletService.open_wallet(sut)
    {:ok, [%WalletOpened{wallet_id: wallet_id}]}
  end

  def execute(%Deposit{wallet_id: id, amount: amount}, %{sut: sut}, _runtime) do
    {:ok, balance} = MyStore.WalletService.deposit(sut, id, amount)
    {:ok, [%Deposited{wallet_id: id, amount: amount, balance: balance}]}
  end
end
```

An unconfirmed clause is stubbed like this (untagged on purpose - it raises):

    def execute(%CloseWallet{} = cmd, _ctx, _runtime) do
      # TODO(pd-model-interview): wiring not confirmed in the interview.
      raise "adapter clause for #{inspect(cmd.__struct__)} not implemented"
    end

## Editing this file

The tagged fences above run in the doc-verification gate
(`elixir scripts/docs_verify.exs`) inside a fresh consumer project: keep them
self-contained (no repo-internal paths), keep the
`<!-- pd-doc-verify: runnable -->` marker on the line immediately above each
fence, and remember elixir fences accumulate top-to-bottom within this file -
later fences see earlier modules. If you change a template, run the gate.
